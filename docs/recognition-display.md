# 작품 이력 표시 규칙

정본은 archive.json의 작품 정보와 수상·상영 원문이다. site.ts의 확인된 행사 정보로 연도·출처를 보완한다. 대표작 note에만 있는 배급 정보는 보조 정보로 사용하며 archive 배급 정보가 우선한다. 원문은 보존하고 표시할 때 정리한다.

- 작품 묶음의 왼쪽 연도: 전체 작업의 작업 연도. 월은 표시하지 않는다.
- 행사 본문: `영화제명 및 부문·결과`. 연도와 월은 화면에서 생략한다. 국가·부문 등 의미 있는 정보는 보존한다. 원본 행사 날짜는 정렬에 사용하며 작업 연도와 혼동하지 않는다.
- 항목 나열은 ` · `로 통일한다. 수상·선정·상영의 의미를 바꾸거나 미확인 실적을 추가하지 않는다.
- 플랫폼: `상영 플랫폼 · Apple TV · 왓챠`. 기존 공개 정보이며 현재 서비스 여부를 검증했다는 뜻은 아니다. `상영 중` 표현은 사용하지 않는다.
- `Google Play 영화, 무비`는 `Google Play 무비/TV` 한 항목으로 표시한다. [Google 공식 표기](https://support.google.com/googleplay/answer/2851683?hl=ko)를 따르며, 현재 Google TV 앱 제공 여부와 작품의 현재 이용 가능 여부를 혼동하지 않는다.
- 배급: `배급 · ㈜씨엠닉스`. 자료가 없는 플랫폼·배급사는 빈칸이나 추정값을 만들지 않는다.
- 대표작: 주요 행사 이력 최대 2개 → 플랫폼 → 배급사 → 나머지 행사 이력 더보기. 추가 행사가 없으면 더보기 없음.
- Studio: 같은 작품 안에서 행사 → 플랫폼 → 배급사 순. 기본 3작품과 나머지 작품 더보기 유지.

현재 메인 대표작과 Studio가 같은 정리 함수를 사용한다. 전체 작업 표와 관리자 입력 원문은 이번 작업에서 변경하지 않는다.

확인 명령: `node --test scripts/recognition.test.mjs`, `npm run build`, `npm run check`.
