# 메인 문구 및 이력 정리

## 후속 사용자 정정: 문구 축약 롤백

히어로·서비스 설명·Studio 소개·문의 설명은 축약 전 문구로 복원. 제목은 작은 영문 라벨 + 한글 제목 구조로 복원하며 `Selected work`는 `Work`로 표시한다. 서비스·툴 순서, 영상 편집의 범용 제목, 현장 오퍼레이팅 표현, 이력 그룹화, 주소 비공개, 관리자 게시 동기화 루틴은 유지한다. 아래는 최초 구현 계획이다.

사용자 디자인 피드백을 구현한다. 히어로는 사운드 중심 포스트 프로덕션, 서비스는 영화/음악/편집/라이브 순. Work/Services/Clients/uniStudio/Contact 제목 하나씩 사용한다.

- 대표작 표시 연도 제거(데이터 보존), 이력은 기존 archive와 site 기록에서 표시. 군·팬미팅 건수 제거 및 현장 오퍼레이팅 표기.
- Studio 이력은 작품별 묶음과 archive 작업 연도 사용. 행사 연도는 본문에 유지하고 월은 제거. 배급·공개 기록도 같은 작품 안에 표시. 첫 3작품과 더보기로 분리.
- 툴은 Pro Tools/Cubase/Ableton Live/Premiere Pro/After Effects/Photoshop/iZotope/Waves/UAD. 실제 화면에서 식별 가능하여 색상 유지.
- 자격 PDF는 추가하지 않음. Clients의 '의', 개업 전 문구, Contact 사업자 블록 제거. 공통 푸터 사업자 기본정보 유지. 공개 intro 주소도 제외, site 데이터의 실제 사업장 정보는 보존.
- 주소: 전자상거래법 제10조는 전자상거래 사이버몰에 주소 표시를 요구한다. 현재 작품 소개·문의용 구조를 기준으로 공개 화면에서 제외. 결제 버튼 유무만으로 통신판매 여부가 결정되지는 않으며 이메일로 소비자 주문을 받는 운영으로 바뀌면 제13조 등 재검토 필요. 법률 자문 아님. 확인 출처 https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1027062761
- 검증: 묶음 데이터 테스트, build/check, PC·모바일 레이아웃과 더보기, 소개서 1쪽 검증.
- 후속 요청: 커밋·푸시 전 원격 관리자 게시 확인 및 안전한 동기화. docs/publish-preflight.md 및 Git 훅 참조.
