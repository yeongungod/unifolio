# 노션에서 포트폴리오 관리

**미리보기는 이 PC에서만 열린다.** 노션 편집·미리보기 실행만으로 사이트에 게시되지 않는다.

## 최초 연결

1. Notion 개발자 설정 https://www.notion.so/profile/integrations 에서 사이트용 내부 연결을 만든다. 콘텐츠 읽기 권한만 허용한다.
2. Portfolio 데이터베이스의 연결 메뉴에서 그 연결을 추가한다.
3. 저장소의 `.env.notion.example`을 `.env.notion.local`로 복사하고, `NOTION_TOKEN=` 뒤에 토큰을 **로컬 편집기에서만** 입력한다. 대화로 보내지 않는다.
4. 작업 폴더는 `C:\Users\yeongungod\Documents\GitHub\unifolio`다. Node 24 이상과 기존 npm 설치를 사용한다.

`.env.notion.local`은 Git 제외다. 대화에 연결된 Notion MCP는 이 프로그램의 API 인증을 대신하지 않는다.

## 노션 입력

노션 [사이트 관리 보기](https://www.notion.so/13c50bd8fe2d81de8b63e247ae0e4b4e?v=3e150bd8fe2d81e48b03000c445246c5)에서 작품을 추가한다. `사이트 대표작`은 순서·문구 편집용, `사이트 제외`는 미체크 작품 확인용이다.

작품명 Name, 연도 Date(숫자), 분야 Platform, 역할 Process, Client를 입력한다. 기존 기록의 역할·클라이언트 공란은 그대로 유지된다.

- **사이트 공개:** 사이트에 반영할 후보만 체크. 대외비는 미체크. 체크해도 즉시 게시되지 않는다.
- **전체 작업 표시:** `/work`에 표시할 개별 작품은 체크. 여러 작품을 묶은 대표 카드는 미체크.
- **대표작 순서:** 메인에 넣을 작품은 1~9. 중복 없이 입력. 비워두면 전체 작업에만 표시.
- **영상 URL:** HTTPS 링크. 유튜브 영상이면 기존 클릭 재생을 사용한다.
- **썸네일:** Notion 파일 속성에 JPG/PNG/WebP 한 개 업로드, 8MB 이하. 일반 외부 영상에는 필수, 유튜브는 생략 가능.
- **한 줄 소개:** 카드에 표시할 설명.
- **사이트 표시명 / 사이트 연도 표기 / 사이트 역할 표기 / 사이트 클라이언트 표기:** 원래 기록과 다르게 표시할 때만 입력. 표시용 값이 있으면 원래 값보다 우선한다.

기존 대표작의 로컬 포스터는 연결된 작품 ID로 유지한다. 바꾸려면 썸네일 속성에 새 파일을 올린다. 유튜브에 썸네일을 직접 올리면 그 이미지가 우선한다.

노션 본문과 내부 메모는 가져오지 않는다. 대표작은 최대 9개, 소개서는 앞 6개를 사용한다.

## 미리보기

```powershell
npm run portfolio:preview
```

Windows에서는 저장소의 `portfolio-preview.cmd`를 더블클릭해도 된다. 노션에서 선택한 작품을 가져와 사이트 사본을 만든 뒤 http://127.0.0.1:4322 에 접속한다. 터미널에 미리보기 번호가 나온다. 종료는 Ctrl+C.

연결 전 기존 데이터로 동작만 확인:

```powershell
npm run portfolio:preview -- --current
```

이 경우 화면에 **기존 파일 사본 (노션 동기화 전)**이라고 표시한다.

이전 사본 다시 보기:

```powershell
npm run portfolio:preview -- --snapshot <미리보기-번호>
```

사본은 `tmp/portfolio-previews/<번호>/`에 보관된다. Git에서 제외되어 있지만 암호화된 보관소는 아니므로 PC 파일 접근 권한을 따른다. 공유 링크·터널·GitHub PR로 사본을 올리지 않는다.

## 확인 후 공개용 파일에 반영

미리보기의 `/`, `/work`, `/intro`와 이미지·연락처를 확인한다. 노션을 더 수정했다면 미리보기를 새로 만든다.

**공개해도 되는 내용을 모두 확인한 뒤에만** 아래 명령을 실행하거나 해당 번호의 반영을 요청한다.

```powershell
npm run portfolio:apply -- <미리보기-번호>
npm run build
npm run check
```

apply는 검토한 사본의 데이터와 새 이미지 사본만 공개용 파일로 옮긴다. 노션을 다시 읽지 않는다. 기존 파일 백업은 미리보기 폴더의 backup/에 남는다. 이후 `git add` 대상이 될 수 있으므로 대외비가 있으면 이 단계를 실행하지 않는다.

공개 해제한 작품의 동기화 이미지(`images/notion/`의 해시 이름 파일)는 다음 반영에서 공개 폴더에서도 제거하고 backup/에 보존한다. 과거 Git 커밋이나 이미 배포했던 파일의 공개 이력까지 지워지는 것은 아니다. 수동으로 보관한 기존 `images/work/`는 자동 삭제하지 않는다.

미리보기 후 사이트 소스나 사본이 바뀌면 반영을 거부한다. 새 미리보기를 만들고 다시 확인한다. 정상 반영 후에도 **커밋·push는 별도 사용자 요청이 필요**하다. Vercel CLI·배포 훅은 사용하지 않는다.

소개서 작품이 바뀌면 `npm run pdf`로 A4 한 장인지 확인한다. G: PDF는 웹 빌드만으로 갱신되지 않는다.

## 오류

- 연결 없음/401/403/404: 로컬 토큰과 해당 Portfolio의 연결 권한을 확인한다.
- 400: 위 속성 이름·타입을 확인한다. 기존 노션 필드는 임의로 바꾸지 않는다.
- 목록이 비어 있음: 사이트 공개·전체 작업 표시·대표작 순서를 확인한다. 실수로 전체 목록을 지우지 않도록 빈 결과는 중단한다.
- 이미지 오류: Notion 파일 속성에 직접 업로드한다. 일반 외부 이미지 주소는 받지 않는다.
- 4322 포트 사용 중: 기존 미리보기 터미널에서 Ctrl+C 후 실행한다. 다른 포트로 자동 공개하지 않는다.
- 다른 반영 실행 중: 진행 중인 터미널을 확인한다. 강제 종료로 `tmp/portfolio-apply.lock`이 남았다면 원본과 backup/을 확인한 뒤 잠금을 제거한다. 실행 중에는 잠금을 지우지 않는다.

API/이미지 실패 시 기존 공개용 파일과 마지막 완료 사본은 바뀌지 않는다.

## 최초 구성 기록 (2026-09-21)

현재 대화의 Notion 연결로 실제 데이터를 읽어 작업 117개·대표작 9개의 로컬 사본을 검증했다. 영상 링크는 3개다. 추가한 해군·공군/온사이드 묶음 2개는 작업 건수에 더하지 않는다. 기존 사이트와 대응하지 않는 기록 4개는 사이트 제외 상태다.

이 PC의 **최초 연결 완료**: `uniStudio Portfolio Local`은 Portfolio에만 연결된 콘텐츠 읽기 전용 연결이다. 사용자 정보·댓글·편집·삽입 권한은 없다. 인증 정보는 Git 제외 `.env.notion.local`에 저장했다. 새 PC에서는 위 최초 연결 절차가 필요하다.

`npm run portfolio:preview`로 실제 Notion API 동기화를 확인했다. 검증한 사본은 `165578d8-3568-4719-9cf6-37c6f43a890d`이며 작업 117개·대표작 9개·영상 링크 3개다. 노션 수정 후 기존 미리보기를 종료하고 다시 실행하면 새 사본을 만든다. 새로고침만으로 노션 수정 내용이 동기화되지는 않는다. 공개용 apply·commit·push는 실행하지 않았다.

## 공개 반영 기록 (2026-09-22)

사용자가 위 사본을 보며 디자인 수정을 요청하고 공개 사이트 push를 지시했다. 해당 사본의 117개·대표작 9개·영상 링크 3개를 `portfolio:apply`로 반영한 뒤 요청한 문구·레이아웃·툴 로고를 수정했다. 과거 사본은 당시 화면 보관용이며, 이후 반영에는 새 미리보기를 만든다. 토큰과 미리보기 사본은 배포 대상이 아니다.
